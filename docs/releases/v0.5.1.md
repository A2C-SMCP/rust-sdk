## v0.5.1 升级提示（旧版本卸载遗留）

如果你在 **0.2.2–0.5.0**（0.5.1 之前已发布的全部版本）上卸载过 marketplace 中的「相对 source」插件，
升级后直接重装可能报 `plugin root not found after source resolution`（`marketplace refresh` 无法可靠
自愈：`git pull` 通常保留本地删除）。

执行恢复前，先确认该插件路径在 **marketplace 上游仓库**（远端提交树）确实存在——本地 clone 就是被
破坏的仓库，上游 manifest 失真也会报同一错误；那种情况需要修 manifest，不要 remove。确认是旧版卸载
遗留后：

1. `marketplace info <name>` + `plugin list --available` —— 记下源 URL、注册名、autoUpdate 旗标，
   以及各插件的 scope/projectPath/version（`remove` 后 `marketplace info` 即查不到 URL；含 token 的
   URL 请从自己的记录取；`plugin list` 默认隐藏 installed-disabled）。**注意：真正受损的插件已被旧版
   uninstall 移除账本与安装意图，`plugin list`/`plugin info` 可能查不到——这些值从其原安装命令、shell
   历史或备份取；取不到就按默认 user/当前版本恢复。**
2. `marketplace remove <name>` —— **默认级联卸载该 marketplace 下所有已安装插件并撤销 trust**；
   **不要用 `--keep-plugins`**（只跳过级联，仍删 clone 并撤销 trust，留下孤儿账本记录）。
3. `marketplace add <git-url> --trust` —— 重新 clone 并重新授予 trust；
   **注册名取清单顶层 `name`（#272）**，`--name` 只作期望名校验、不再改名；若清单名与旧注册名不同，
   `<plugin>@<old-name>` 引用会失效（见下方「Marketplace 身份语义变更」）；
   原来开过 auto-update 的加 `--auto-update`。
4. 逐一按原 scope `plugin install <plugin>@<name> --scope <scope>` —— 缺省为 user；多 scope 插件每个
   scope 各装一次；project/local 必须在原项目目录执行（cwd 即 projectPath）。`--version` 只恢复账本
   version 字段、不锁定内容（需锁定内容须在 marketplace 源仓库侧用原 commit/ref）。此前启用过的再
   `plugin enable <plugin>@<name>`。

详见 [旧版本 → 0.5.1 升级迁移](https://github.com/A2C-SMCP/rust-sdk/blob/v0.5.1/docs/computer/marketplace-0.5.1-migration.md)。

## v0.5.1 行为变更：reconcile 声明式换源改为拒绝

`reconcile()` 遇到同名不同源（runtime-contract §5.14）时不再 wipe + re-clone，而是**拒绝**：旧注册、旧物化
内容与旧运行时能力保持不变，拒绝项归 `ReconcileReport.failed`（结构化日志 reason 为
`marketplace_source_conflict` / `marketplace_source_unusable`）。换源须显式 `marketplace remove` 后 re-add。

- **不要对 `failed` 一律自动重试**：它同时包含可重试的 clone/pull 失败与不可重试的 §5.14 冲突；后者须先修
  配置并显式 remove + re-add。
- 拒绝分支不执行 stage：启动对账若用空 `SkillRegistry`，请先跑 recovery（或传入既有 Registry），否则被拒
  marketplace 的旧 SKILL 不会出现在该 Registry（账本与 clone 树不受影响）。

## v0.5.1 行为变更：boot 恢复补声明面换源诊断（#295）

boot 恢复（`recover_marketplace_skills` / `reconcile_governance` 阶段一）此前只按 `known_marketplaces` 的
注册 source 恢复，不比对 settings 的 `extraKnownMarketplaces`：用户在声明面把已注册 marketplace 换到另一个
仓库后重启，旧源被**静默沿用**。现在检测到声明 source 与注册 source 不再同源（runtime-contract §5.14）时：

- **拒绝声明变更、不静默沿用**：恢复仍按**已注册 source** 进行（旧能力保留）。已存在 clone 树不 wipe、
  不按声明源重 clone；clone 缺失时仍从注册 source clone。冲突项写入新增的
  `GovernanceRecoveryReport.marketplace_source_conflicts`（脱敏展示值），并输出
  `reason="marketplace_source_conflict"` 的结构化 WARN 与 CLI 提示。
- **不进入 degraded**：§5.14 属 validation 拒绝，旧注册能力保持 active（同上方 reconcile 的口径）。
- **换源须显式迁移**：`marketplace remove <name>`（默认级联卸载）后 `marketplace add <git-url>` 重新注册。
- 同源（`Same`）照常恢复、无提示。
- 公开 API：`GovernanceRecoveryReport` 新增 pub 字段 `marketplace_source_conflicts`（外部 struct literal
  构造会受影响；report 未加 `#[non_exhaustive]`）。
- **谓词已统一（#267/#302）**：`reconcile()` 与 boot 恢复现在都经 `compare_marketplace_sources`
  （仅 `Same` 才算同源；写法不同 / 形态非法 = `Unverifiable` → fail-closed）。`marketplace_source_unusable`
  仅保留给「注册与声明 source 精确同形且不可克隆」；不同 URL（即使声明侧不可用）与不同写法一律记
  `marketplace_source_conflict`（#294 安全语义）。额外 source 键（如 `ref`）不参与身份，账本归一为
  `{type,url}`（与 python `same_source` 对齐）。
- **非法声明已可观测（#302）**：声明条目缺失 / 非法 `source` 仍在 settings 校验阶段被整条丢弃，
  但错误现在进入 `GovernanceRecoveryReport.marketplace_declaration_errors`
  （`scope` / `marketplace` / `field` / `reason` / `source_path`），boot 汇总日志与 CLI 恢复输出会给出
  脱敏警示（`declaration ignored; existing registration unchanged`）；不计入
  `marketplace_source_conflicts`、不降级。公开 additive 字段：`GovernanceRecoveryReport` 未加
  `#[non_exhaustive]`，外部 struct literal 构造会因新字段编译失败；`MarketplaceDeclarationError` 为
  `#[non_exhaustive]`。诊断中的字段/原因已剥离 Git URL 凭据（含 path 内百分号编码凭据）并清洗
  控制/格式字符；`source_path` 只做控制字符清洗（路径按路径对待，不做 URL 归一）。
  **flag 重复呈现已收敛（#301）**：`reconcile_governance` 的实例解析合入 flag 层后，报告字段
  `marketplace_declaration_errors` **过滤 `SettingsScope::Flag` 条目**（CLI 启动边界经
  `format_settings_errors` 单独打印 flag 校验错误，避免 remount/approval 重复警示）；WARN 日志仍记录
  全量（含 Flag），非 CLI 嵌入方可直接调用 `resolve_settings(flag_settings_path=…)` 读取全量校验错误。

## v0.5.1 Marketplace 身份语义变更（#272，破坏性）

Marketplace 注册名改为**清单顶层 `name`**（严格 kebab-case），URL 只作定位：

- 新 `marketplace add` 先 clone/读清单再定名；清单 `name` 缺失或非法 → `validation` 失败，**不回退
  URL 派生名**。仓库名与清单名不同时以清单名为准。
- `AddMarketplaceParams.name` / CLI `--name` 退化为**期望清单名校验**，不再覆盖注册名；不匹配 → 报错。
- **同名同源重复 add 幂等**（成功、`changed=false`，不产生第二份注册）；**同名不同源**拒绝；
  **同源以旧名 add** 拒绝；同源无法判定（ssh/https 等价写法）→ fail-closed。
- `marketplace refresh` 遇清单改名 → 新增 `rejected` 行状态 + 结构化诊断；旧注册 / 旧内容 / 旧能力
  保留，不进入 degraded，既有 `<plugin>@<old-name>` 引用不被静默重写。
- legacy 注册（无 `manifestNameBaseline`）首次成功 refresh 记录基线并**保留旧名** + advisory；之后
  再改名才拒绝。账本新增 `manifestNameBaseline` 一等字段（#289 迁移依赖）。
- `--no-clone` 仅在**已有 catalog + `--name` 且清单匹配、同源可证**时成功；否则 `validation`。
- CLI trust 时序：交互确认按脱敏 URL 展示；**注册成功后才写 `trustedMarketplaces`**，写失败回滚本次
  注册。
- 公开 API（破坏面）：
  - 移除 `resolve_marketplace_identity` / `MarketplaceIdentity`，新增 `resolve_marketplace_add_request`。
  - `RefreshStatus` 新增 `Rejected`（已 `#[non_exhaustive]`）；`MarketplaceRefreshRow` 新增 `diagnostic`
    （类别含 `manifest_unreadable` / `legacy_manifest_name_mismatch` / `legacy_manifest_name_missing` /
    `legacy_manifest_name_invalid`）；`MarketplaceAddOutcome` 新增 `changed` / `created` / `flags_updated`；
    `AddMarketplaceParams` 新增 `config_cwd`。
  - `GovernanceError` 新增变体 `Validation(MarketplaceStageError)` / `SourceEquivalenceUnknown` /
    `SourceAlreadyRegistered` / `MarketplaceNameReferenced`（该 enum 非 `#[non_exhaustive]`，下游穷举
    `match` 需补分支）。
  - `KnownMarketplaceEntry` 新增 pub 字段 `manifest_name_baseline`（下游 struct literal 需补字段或
    `..Default::default()`）。
  - `default_marketplace_name` 保留为 legacy URL 派生工具，add 不再使用。
- 升级提示：对 legacy 源执行一次 `marketplace refresh` 建立基线；真正的改名迁移用
  `marketplace migrate`（见下节），不要把 `remove` + `add` 当作无损迁移。详见
  [Marketplace 身份模型](https://github.com/A2C-SMCP/rust-sdk/blob/v0.5.1/docs/computer/marketplace-identity.md)。
- 性能提示：为了让 `git merge --ff-only` 可判定，shallow clone 的**首次** refresh 会先 `--unshallow`
  拉取完整历史（一次性成本，之后增量 fetch）；大仓库首次 refresh 会明显变慢。

以下与上方各节同批交付，但属于下游**穷举 `match` / struct literal** 会编译失败的破坏面：

- `GovernanceRecoveryReport` 新增 `marketplace_source_conflicts`（#295）与

## v0.5.1 剩余身份守卫：reconcile/install refresh 改名 + 声明式 re-add + flag/policy 引用层（#267）

补齐 `marketplace refresh` 之外两条 refresh 路径的 §5.14 身份守卫，并把 remove/re-add 引用门补到五层
settings：

- **reconcile `autoUpdate` / 显式 `refresh`**：来料清单改名（或缺失 / 非法 / 损坏）→ 归 `ReconcileReport.failed`
  并输出 `reason="marketplace_manifest_name_changed"` / `_name_missing` / `_name_invalid` /
  `_manifest_unreadable` 的结构化 ERROR；**不注销 SKILL、不删 clone、不写账本**，旧注册/旧内容/旧能力保持
  active（validation，不进入 degraded）。clone 缺失但已注册 baseline 的重克隆同样先校验改名。
  同源更新照常收敛。**行为变更**：clone/pull / staged 回退失败（网络 / I-O）一律归 `failed`（可重试、
  已降级）；此前「clone 仍在」会归 `updated`，与「刷新失败」语义矛盾。`ReconcileReport` 公共字段不新增。
- **`install_plugin{refresh:true}`**（公开 SDK API；CLI `plugin install` 仍固定 `refresh:false`）：先刷新并
  校验 catalog 工作副本，改名拒绝发生在任何物化（含外部 plugin clone）与 registry 变更之前，返回
  `PluginInstallError::Staging`（并输出与 reconcile 同口径的 `reason` ERROR）；网络失败保留既有「使用旧
  catalog 继续」的降级。legacy（无基线）注册的首次成功 refresh 会钉住来料清单名并给 advisory（与
  `marketplace refresh` / reconcile 同语义）。
- **声明式 re-add 引用门**：reconcile 在「账本 + clone 均缺失」且 `installedPlugins` **安装意图**仍含
  `<plugin>@<name>` 时拒绝（`reason="marketplace_dangling_references"`），不 clone / 不注册 / 不写账本。
  仅 `enabledPlugins` 残留（安装意图为空）**不阻断** reconcile——那是首次声明式安装与期望态的合法形态；
  显式 `marketplace add` 路径仍由完整引用守卫拦截。
- **add 路径引用守卫补 flag/policy 层**：reference guard 现在消费五层合并视图（`--settings` 的 flag 层与
  policy 层 `enabledPlugins` 一并计入，true/false 均算意图引用），并与安装意图取并集。解析在账本锁外完成，
  锁内只判空。`Computer::add_marketplace` 以**实例** flag/policy 视图覆盖调用方注入（宿主不能传入空/过期
  视图绕过守卫）。
- **工作树自愈与并发绑定**：refresh 读取的清单绑定本进程校验过的 sha（不再用可被并发 fetch 改写的
  `FETCH_HEAD`）；本地工作树清单不合法而上游来料合法时经 staged swap 自愈，来料也不合法才拒绝；
  same-commit 复用的 baseline 以 HEAD 裁决，不用本地脏工作树裁决。
- 公开 API（破坏面）：
  - `AddMarketplaceParams` 新增 `flag_settings_path` / `policy_settings`；`cli` feature 下的
    `MarketplaceAddOptions` 同步新增 `flag_settings_path`（下游 struct literal 均需补字段或
    `..Default::default()`）。
  - `SkillGovernanceStore::load_installed_plugins_intent` **移除默认实现**（原默认返回空，会让未覆写的外部
    store 在声明式 re-add 引用门上静默 fail-open）。自定义 store 实现方必须提供真实安装意图快照。
- 性能提示：`install_plugin{refresh:true}` 与 reconcile refresh 复用与 `marketplace refresh` 相同的
  fetch→ff / staged-swap 路径；shallow clone 的首次 refresh 会 `--unshallow`（一次性成本）。
- 镜像说明：item 1/2 的等价行为 python-sdk 已在 #260 实现；item 3（flag/policy 引用层）为双端同缺口，
  python 侧镜像评估另行跟进。

## v0.5.1 新命令：`marketplace migrate`（#289）

存量 marketplace 注册名（0.5.1 前的 URL 派生名 / 显式 `--name` 别名）可显式迁移到清单顶层 `name`：

```text
marketplace migrate                                  # dry-run（默认，零写入）
marketplace migrate --apply                          # 迁移
marketplace migrate --apply --update-declarations    # 同时改 user 的 extraKnownMarketplaces
marketplace migrate --resume                         # 中断后续做
marketplace migrate --rollback <timestamp>           # 按备份回滚
```

- **离线**：执行前请停止所有 Computer / python 实例；命令不 clone、不触网。
- 改写范围：安装/启用意图、trust / blocked、plugin-scoped keyring secret（含已从清单移除但账本仍有
  安装记录的 plugin）、账本/catalog 派生目录；project/local 只报告（旧 `enabledPlugins` 键迁移后会
  失活、旧 trust/blocked 名会失效，均 exit 3 提示）；flag/policy 请手动核对。
- 冲突（同名双旧名、新名被占、裸名冲突等）整体 abort、零写入；退出码 0 / 1（冲突）/ 3（部分完成）。
- 自动备份到 `<A2C_SKILL_HOME>/marketplace-migration-backup-<timestamp>/`，支持 `--resume` / `--rollback`；
  备份不会自动清理；journal 在成功 / 回滚完成后删除（异常中断时保留供 `--resume`）。
- 与 python-sdk#268 语义一致（python 为 forward-only，无回滚；差异已在 protocol Discussion#81 留痕）。
- **重装 caveat（属 `plugin install`，不在 migrate 内）**：`plugin install --version` 只恢复账本 version
  字段、不锁定内容（#278）。
- 详见 [存量 Marketplace 注册名迁移](https://github.com/A2C-SMCP/rust-sdk/blob/v0.5.1/docs/computer/marketplace-name-migration.md)。

## v0.5.1 行为变更：`--settings`（flag 层）运行期治理解析全部生效（#248/#301 残余）

0.5.0 的运行期 flag seam 只覆盖 `readRoots` / `landingRoot`：`--settings` 文件里的 `enabledPlugins` 在
`settings show` 可见，但治理恢复、待批准列表、归属视图、config CRUD 快照与 GUI 治理快照都按「无 flag 层」
解析。v0.5.1 起**五个**解析点统一消费**实例** flag settings（`with_flag_settings_path` 构造期归一的路径）
并以**实例 env** 解析 policy：

- `reconcile_governance`（`declared=None` 内部解析与 `declared=Some` 的 per-scope origin 判定两路径）：
  flag-only `enabledPlugins=true` 也会恢复 SKILL 并重挂 bundled server；flag 受信（免批准），
  `flag=true + project=true` 不再误落 project-origin 的 PENDING。跨重启可靠启用除 user scope 外，也可在
  每次 boot 注入同一 `--settings` flag 文件（CLI 参考接线）。
  **调用方 `declared` 与受信层的一致性**：实例 flag/policy 的显式 `enabledPlugins` 值会覆盖调用方传入的
  `declared.enabledPlugins`——flag-blind caller 的旧视图不能把受信层的显式 disable 压成 enable（反之亦然）；
  其余键与其他 scope 仍以调用方为准。
- `list_pending_bundled_approvals`：flag `false` 可压过 project `true`（已禁用的项不再出现在待批准列表）。
- `enabled_bundled_ownership`（`managedBy=plugin` 与 `remove_server` 的 Synthesized 门控）：project/local
  锚点改为**实例 `config_dir`**（此前退回进程 cwd，嵌入宿主 `with_config_dir` 下会漏判）；并纳入 flag 层。
- `instance_config_context`（runtime config CRUD 快照）：纳入实例 flag settings 层。**有意不接**
  `--mcp-config` flag（与 python `upsert_mcp_server` 的「origin 快照 flag-less、写后遮蔽 WARN」口径一致，
  避免 rust 单侧更严）与 `policy_settings`（借用字段；快照中 `None` = 空 policy 层，非 ambient policy）。
- `governance_snapshot`（GUI 的 `list_plugins` / `get_plugin` / `GovernanceSnapshot.revision` 来源）：
  同步纳入实例 flag settings 层与实例 env 解析的 policy，消除「`enabled=false` 但
  `materialized_mcp_servers` 非空」的同快照自相矛盾；flag 内容切换会改变 revision（GUI 缓存可正常刷新）。
- 一致性附带修正：`resolve_landing_root_settings` / `readRoots` 的 policy 解析也改为**实例 env**
  （此前传进程 env；remote policy 落地后避免同一实例两套 policy 层）。

**policy 口径（逐点三列，避免「同源」歧义）**：

| 解析点 | flag settings | ambient policy（实例 env） | 借用 `policy_settings` 字段 |
|---|---|---|---|
| `reconcile_governance` / `list_pending_bundled_approvals` / `enabled_bundled_ownership` / `governance_snapshot` | 统一消费 | **是** | 不接 |
| `instance_config_context`（config CRUD 快照） | 统一消费 | **有意不接** | **是**（`None` = 空 policy 层，非 ambient） |

`landingRoot` / `readRoots` 的 policy 解析也改为**实例 env**。

行为提示：经 `--settings` 启用的插件现在会在运行期真实激活（技能出现、bundled MCP 挂载）；使用
`with_config_dir` 的嵌入宿主，project/local-scope 的启用态开始参与 `managedBy` 与 CRUD 归属判定。

**已知缺口（如实声明）**：

- **policy 层无测试注入 seam**：`resolve_policy_settings` 的 OS 级子源（macOS plist / Linux
  `/etc/a2c-computer` / Windows 注册表）不受注入 env 影响——hermetic 自动覆盖只到 flag 层，policy 接线仅由
  代码评审保障；宿主机若配置企业 policy，会参与实例视图并可能影响本机测试/行为。是否加 policy 注入接缝另案。
- `instance_config_context`（config 快照）与 ownership/governance 仅共享 env / flag / `config_dir`，
  **policy 刻意不接**（借用字段限制）；这是有意的例外，不是「完全同源」。
- `landingRoot` / `readRoots` 的解析配方与上述实例收口仍有重复（DRY 另案，追踪于 #267）。

## v0.5.1 行为变更：MCP import 预检覆盖目标容器畸形（#292/#301 残余）

`preflight_mcp_import` 此前只做文件级 strict 读：目标 `mcp.json` 容器类型畸形（如 `{"servers": []}`）
会被预检判为可导入，随后在 executor 落盘前以 `ImportError::Persist(CorruptTarget)` 失败。v0.5.1 起预检
复用 executor 的 `validate_write_plan`（project `readRoots` 剥离 + 逐层 object/string-set 容器 guard）：

- 容器畸形在 preflight 阶段产出 `field="<file>"` 诊断（reason 前缀 `import target container malformed:`），
  `import_mcp_servers` 返回 `ImportError::Preflight`；**零写保证不变**（目标文件逐字节不变）。
- `Computer::import_mcp_servers` 仍把 config 层错误折叠为 `ConfigPersist(String)`（既有 API 不变），但
  `Computer::preflight_mcp_servers` 现在能提前看到该类诊断。
- 已知边界：preflight 与 executor 之间文件被外部改写仍可能回退到 `Persist`（best-effort）。

## v0.5.1 其他行为与安全修正（#271/#273/#274/#275/#279/#284/#285）

- **enable 内容缺失 fail-fast（#274）**：安装根缺失 / 声明内容不可投影 / 预检期望 SKILL 但零注册 →

## v0.5.1 行为变更：MCP client teardown 有界化（#303 / #267 S4）

`disconnect` / `Computer::shutdown` 不再被不响应的对端拖住。无 wire / 协议变更；`Computer.shutdown`
的公开语义不变（内部同样走 bounded disconnect）。

- **stdio / HTTP**：`disconnect` 改 `RunningService::close_with_timeout(1s)`；超时后 WARN 继续，rmcp 已
  取消 token 并分离服务任务，清理由其自身 5s 上限在后台完成（stdio 子进程另由 SIGKILL + wait 回收）。
- **SSE**：shutdown / exit 改后台投递（固定 shutdown→exit、每条 1s 上限、失败只 WARN）；single-supervisor
  去重（新 supervisor 在同一临界区 abort 旧实例）＋ `connection_epoch` 闸门（同一 client 实例重连后不投递
  迟到 exit）；`disconnect` 硬上界 **≈1.5s**（≤500ms 下发窗口 + ≤1s 流关闭），不等待响应，超窗后由后台
  best-effort 继续投递。
- **上界口径**：1s（stdio/HTTP）与 ≈1.5s（SSE）均为 **per-client** 上界；`Computer::shutdown` 经
  `stop_all` **串行**逐个 disconnect，总耗时随客户端数累加，**不是全局上界**。
- **实测**：HTTP 服务器停 POST 5.0s → ≤1s；SSE 服务器不回包 2.0s → ≈1.5s；stdio 子进程忽略 stdin
  6ms 级（回归栅栏 <500ms + 子进程 pid 回收）。
- **调用方注意**：依赖「`disconnect` 返回即所有清理完全结束」的宿主需复核——HTTP / SSE 的后台清理可能
  仍在途（best-effort），但不会再阻塞 `disconnect` 返回；`shutdown` 返回后立即退出进程，后台投递 /
  清理可能被截断。
