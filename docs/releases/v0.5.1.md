## v0.5.1 升级提示（旧版本卸载遗留）

如果你在 **0.2.2–0.5.0**（0.5.1 之前已发布的全部版本）上卸载过 marketplace 中的「相对 source」插件，
升级后直接重装可能报 `plugin root not found after source resolution`（`marketplace refresh` 无法可靠
自愈：`git pull` 通常保留本地删除）。

执行恢复前，先确认该插件路径在 **marketplace 上游仓库**（远端提交树）确实存在——本地 clone 就是被
破坏的仓库，上游 manifest 失真也会报同一错误；那种情况需要修 manifest，不要 remove。确认是旧版卸载
遗留后：

1. `marketplace info <name>` + `plugin list --available` —— 记下源 URL、注册名、autoUpdate 旗标，
   以及各插件的 scope/projectPath/version（`remove` 后 `marketplace info` 即查不到 URL；含 token 的
   URL 请从自己的记录取；`plugin list` 默认隐藏 installed-disabled）。**注意：真正受损的插件已被旧版
   uninstall 移除账本与安装意图，`plugin list`/`plugin info` 可能查不到——这些值从其原安装命令、shell
   历史或备份取；取不到就按默认 user/当前版本恢复。**
2. `marketplace remove <name>` —— **默认级联卸载该 marketplace 下所有已安装插件并撤销 trust**；
   **不要用 `--keep-plugins`**（只跳过级联，仍删 clone 并撤销 trust，留下孤儿账本记录）。
3. `marketplace add <git-url> --trust` —— 重新 clone 并重新授予 trust；
   **注册名取清单顶层 `name`（#272）**，`--name` 只作期望名校验、不再改名；若清单名与旧注册名不同，
   `<plugin>@<old-name>` 引用会失效（见下方「Marketplace 身份语义变更」）；
   原来开过 auto-update 的加 `--auto-update`。
4. 逐一按原 scope `plugin install <plugin>@<name> --scope <scope>` —— 缺省为 user；多 scope 插件每个
   scope 各装一次；project/local 必须在原项目目录执行（cwd 即 projectPath）。`--version` 只恢复账本
   version 字段、不锁定内容（需锁定内容须在 marketplace 源仓库侧用原 commit/ref）。此前启用过的再
   `plugin enable <plugin>@<name>`。

详见 [旧版本 → 0.5.1 升级迁移](https://github.com/A2C-SMCP/rust-sdk/blob/v0.5.1/docs/computer/marketplace-0.5.1-migration.md)。

## v0.5.1 行为变更：reconcile 声明式换源改为拒绝

`reconcile()` 遇到同名不同源（runtime-contract §5.14）时不再 wipe + re-clone，而是**拒绝**：旧注册、旧物化
内容与旧运行时能力保持不变，拒绝项归 `ReconcileReport.failed`（结构化日志 reason 为
`marketplace_source_conflict` / `marketplace_source_unusable`）。换源须显式 `marketplace remove` 后 re-add。

- **不要对 `failed` 一律自动重试**：它同时包含可重试的 clone/pull 失败与不可重试的 §5.14 冲突；后者须先修
  配置并显式 remove + re-add。
- 拒绝分支不执行 stage：启动对账若用空 `SkillRegistry`，请先跑 recovery（或传入既有 Registry），否则被拒
  marketplace 的旧 SKILL 不会出现在该 Registry（账本与 clone 树不受影响）。

## v0.5.1 行为变更：boot 恢复补声明面换源诊断（#295）

boot 恢复（`recover_marketplace_skills` / `reconcile_governance` 阶段一）此前只按 `known_marketplaces` 的
注册 source 恢复，不比对 settings 的 `extraKnownMarketplaces`：用户在声明面把已注册 marketplace 换到另一个
仓库后重启，旧源被**静默沿用**。现在检测到声明 source 与注册 source 不再同源（runtime-contract §5.14）时：

- **拒绝声明变更、不静默沿用**：恢复仍按**已注册 source** 进行（旧能力保留）。已存在 clone 树不 wipe、
  不按声明源重 clone；clone 缺失时仍从注册 source clone。冲突项写入新增的
  `GovernanceRecoveryReport.marketplace_source_conflicts`（脱敏展示值），并输出
  `reason="marketplace_source_conflict"` 的结构化 WARN 与 CLI 提示。
- **不进入 degraded**：§5.14 属 validation 拒绝，旧注册能力保持 active（同上方 reconcile 的口径）。
- **换源须显式迁移**：`marketplace remove <name>`（默认级联卸载）后 `marketplace add <git-url>` 重新注册。
- 同源（`Same`）照常恢复、无提示。
- 公开 API：`GovernanceRecoveryReport` 新增 pub 字段 `marketplace_source_conflicts`（外部 struct literal
  构造会受影响；report 未加 `#[non_exhaustive]`）。
- 已知限制：`reconcile()`（当前无生产调用点）仍按精确 `Value` 相等判定换源；与 boot 恢复的
  canonical 判定（`Same` 才同源）对「可证明等价写法」的裁决可能不同，谓词统一另行跟进。
- 声明条目缺失 / 非法 `source` 会在 settings 校验阶段被整条丢弃（不进入声明视图）；直接以未校验
  `declared` map 调用 `reconcile_governance(declared=...)` 的嵌入方才会走到「声明缺 source → fail-closed
  冲突」这条原始 API 防御路径（生产路径无此诊断，可观测性 follow-up 已记录）。

## v0.5.1 Marketplace 身份语义变更（#272，破坏性）

Marketplace 注册名改为**清单顶层 `name`**（严格 kebab-case），URL 只作定位：

- 新 `marketplace add` 先 clone/读清单再定名；清单 `name` 缺失或非法 → `validation` 失败，**不回退
  URL 派生名**。仓库名与清单名不同时以清单名为准。
- `AddMarketplaceParams.name` / CLI `--name` 退化为**期望清单名校验**，不再覆盖注册名；不匹配 → 报错。
- **同名同源重复 add 幂等**（成功、`changed=false`，不产生第二份注册）；**同名不同源**拒绝；
  **同源以旧名 add** 拒绝；同源无法判定（ssh/https 等价写法）→ fail-closed。
- `marketplace refresh` 遇清单改名 → 新增 `rejected` 行状态 + 结构化诊断；旧注册 / 旧内容 / 旧能力
  保留，不进入 degraded，既有 `<plugin>@<old-name>` 引用不被静默重写。
- legacy 注册（无 `manifestNameBaseline`）首次成功 refresh 记录基线并**保留旧名** + advisory；之后
  再改名才拒绝。账本新增 `manifestNameBaseline` 一等字段（#289 迁移依赖）。
- `--no-clone` 仅在**已有 catalog + `--name` 且清单匹配、同源可证**时成功；否则 `validation`。
- CLI trust 时序：交互确认按脱敏 URL 展示；**注册成功后才写 `trustedMarketplaces`**，写失败回滚本次
  注册。
- 公开 API（破坏面）：
  - 移除 `resolve_marketplace_identity` / `MarketplaceIdentity`，新增 `resolve_marketplace_add_request`。
  - `RefreshStatus` 新增 `Rejected`（已 `#[non_exhaustive]`）；`MarketplaceRefreshRow` 新增 `diagnostic`
    （类别含 `manifest_unreadable` / `legacy_manifest_name_mismatch` / `legacy_manifest_name_missing` /
    `legacy_manifest_name_invalid`）；`MarketplaceAddOutcome` 新增 `changed` / `created` / `flags_updated`；
    `AddMarketplaceParams` 新增 `config_cwd`。
  - `GovernanceError` 新增变体 `Validation(MarketplaceStageError)` / `SourceEquivalenceUnknown` /
    `SourceAlreadyRegistered` / `MarketplaceNameReferenced`（该 enum 非 `#[non_exhaustive]`，下游穷举
    `match` 需补分支）。
  - `KnownMarketplaceEntry` 新增 pub 字段 `manifest_name_baseline`（下游 struct literal 需补字段或
    `..Default::default()`）。
  - `default_marketplace_name` 保留为 legacy URL 派生工具，add 不再使用。
- 升级提示：对 legacy 源执行一次 `marketplace refresh` 建立基线；真正的改名迁移见 #289，不要把
  `remove` + `add` 当作无损迁移。详见 [Marketplace 身份模型](https://github.com/A2C-SMCP/rust-sdk/blob/v0.5.1/docs/computer/marketplace-identity.md)。
- 性能提示：为了让 `git merge --ff-only` 可判定，shallow clone 的**首次** refresh 会先 `--unshallow`
  拉取完整历史（一次性成本，之后增量 fetch）；大仓库首次 refresh 会明显变慢。

## v0.5.1 剩余身份守卫：reconcile/install refresh 改名 + 声明式 re-add + flag/policy 引用层（#267）

补齐 `marketplace refresh` 之外两条 refresh 路径的 §5.14 身份守卫，并把 remove/re-add 引用门补到五层
settings：

- **reconcile `autoUpdate` / 显式 `refresh`**：来料清单改名（或缺失 / 非法 / 损坏）→ 归 `ReconcileReport.failed`
  并输出 `reason="marketplace_manifest_name_changed"` / `_name_missing` / `_name_invalid` /
  `_manifest_unreadable` 的结构化 ERROR；**不注销 SKILL、不删 clone、不写账本**，旧注册/旧内容/旧能力保持
  active（validation，不进入 degraded）。clone 缺失但已注册 baseline 的重克隆同样先校验改名。
  同源更新照常收敛；网络类失败维持既有降级语义。`ReconcileReport` 公共字段不新增。
- **`install_plugin{refresh:true}`**（公开 SDK API；CLI `plugin install` 仍固定 `refresh:false`）：先刷新并
  校验 catalog 工作副本，改名拒绝发生在任何物化（含外部 plugin clone）与 registry 变更之前，返回
  `PluginInstallError::Staging`；网络失败保留既有「使用旧 catalog 继续」的降级。
- **声明式 re-add 引用门**：reconcile 在「账本 + clone 均缺失」且 `installedPlugins` **安装意图**仍含
  `<plugin>@<name>` 时拒绝（`reason="marketplace_dangling_references"`），不 clone / 不注册 / 不写账本。
  仅 `enabledPlugins` 残留（安装意图为空）**不阻断** reconcile——那是首次声明式安装与期望态的合法形态；
  显式 `marketplace add` 路径仍由完整引用守卫拦截。
- **add 路径引用守卫补 flag/policy 层**：reference guard 现在消费五层合并视图（`--settings` 的 flag 层与
  policy 层 `enabledPlugins` 一并计入，true/false 均算意图引用），并与安装意图取并集。解析在账本锁外完成，
  锁内只判空。
- 公开 API（轻破坏）：`AddMarketplaceParams` 新增 `flag_settings_path` / `policy_settings`
  （下游 struct literal 需补字段或 `..Default::default()`）。
- 性能提示：`install_plugin{refresh:true}` 与 reconcile refresh 复用与 `marketplace refresh` 相同的
  fetch→ff / staged-swap 路径；shallow clone 的首次 refresh 会 `--unshallow`（一次性成本）。
- 镜像说明：item 1/2 的等价行为 python-sdk 已在 #260 实现；item 3（flag/policy 引用层）为双端同缺口，
  python 侧镜像评估另行跟进。
